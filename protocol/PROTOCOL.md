# Протокол RemoteDesk — v1 (этап M0)

Связь между приложением на телефоне («клиент») и агентом на ПК («агент»).

## Транспорт
- **WebSocket поверх TLS** (`wss://<ip>:<port>/ws`), порт по умолчанию **47800** (настраивается в агенте).
- Сертификат агента самоподписанный (ECDSA P-256), создаётся при первом запуске и хранится в `%APPDATA%\RemoteDesk\agent.pfx`.
- Клиент **закрепляет** сертификат: принимает соединение, только если SHA-256 от DER-сертификата совпадает с отпечатком, полученным при сопряжении (`fp`). Имя хоста не проверяется — проверяется только отпечаток.
- Сообщения управления — текстовые кадры JSON (UTF-8). Поле `t` — тип сообщения. Для частых событий ввода (этап M1) появятся бинарные кадры.

## Поиск в сети (mDNS / DNS-SD)
Агент объявляет службу **`_rdesk._tcp.local`** на своём порту. TXT-записи:

| Ключ | Значение |
|---|---|
| `v` | версия протокола (`1`) |
| `id` | идентификатор агента (UUID без дефисов) |
| `name` | имя компьютера |
| `fp` | отпечаток сертификата (base64url без `=`) |

Клиент по `id` узнаёт уже сопряжённые компьютеры и обновляет их IP-адрес. Новый компьютер из mDNS можно сопрячь только кодом (см. ниже) — отпечаток из mDNS сам по себе не доверенный.

## Сопряжение

### По QR-коду (основной способ)
Агент показывает QR-код со ссылкой:
```
rdesk://pair?v=1&id=<agentId>&n=<имя ПК>&h=<ip1,ip2>&p=<порт>&fp=<отпечаток>&k=<ключ>
```
- `h` — все IPv4-адреса ПК в локальных сетях, `k` — одноразовый ключ сопряжения (16 случайных байт, base64url), живёт 10 минут и обновляется после каждого успешного сопряжения.
- Клиент подключается к любому адресу из `h` с закреплённым `fp` и шлёт `pair` с `secret = k`.
- QR-код передаёт отпечаток по «оптическому каналу», поэтому подменить агента в сети нельзя.

### По 6-значному коду (запасной способ)
- Агент показывает код `123456` (живёт 5 минут), клиент находит ПК через mDNS и шлёт `pair` с `secret = "123456"`.
- После 5 неверных попыток подряд код сбрасывается, новый — через кнопку в агенте.
- Отпечаток в этом случае пришёл из mDNS. Чтобы исключить подмену, обе стороны после сопряжения показывают **4 слова-проверки**, вычисленные из отпечатка; пользователь сверяет их глазами. (Этап M1, в M0 — только QR.)

### Обмен
```
клиент → {"t":"pair","secret":"…","deviceId":"…","deviceName":"Pixel 8","platform":"android","appVersion":"0.1.0"}
агент  → {"t":"paired","token":"…","agent":{…AgentInfo}}
```
`token` — 32 случайных байта (base64url), постоянный пароль этого телефона. Агент хранит только SHA-256 от токена. Клиент хранит токен вместе с `id`, `fp` и адресами агента.

## Подключение сопряжённого телефона
```
клиент → {"t":"hello","deviceId":"…","token":"…","appVersion":"0.1.0"}
агент  → {"t":"welcome","agent":{…AgentInfo},"permissions":["input","power","files","clipboard","screen"]}
```
Пока не прошли `pair` или `hello`, агент принимает только эти два сообщения; на остальные отвечает `error` `not_authenticated` и закрывает соединение.

### AgentInfo
```json
{
  "id": "…", "name": "DESKTOP-ABC123", "os": "Windows 11 Pro 26200",
  "version": "0.1.0", "protocol": 1,
  "macs": [{"mac": "AA:BB:CC:DD:EE:FF", "name": "Ethernet", "ip": "192.168.0.102", "wired": true}]
}
```
`macs` нужны клиенту для Wake-on-LAN — пользователю не придётся вводить MAC вручную.

## Служебные сообщения
| t | Направление | Поля | Смысл |
|---|---|---|---|
| `ping` | клиент → агент | `n` (число) | Проверка связи, раз в 5 с |
| `pong` | агент → клиент | `n` | Ответ с тем же `n`; клиент считает задержку |
| `error` | агент → клиент | `code`, `msg` | Ошибка. Коды: `bad_secret`, `secret_expired`, `too_many_attempts`, `not_authenticated`, `revoked`, `bad_message`, `unsupported_version`, `forbidden`, `power_failed` |
| `bye` | обе стороны | `reason?` | Вежливое закрытие |

Неизвестные поля игнорируются, неизвестный `t` → `error` `bad_message` (соединение не рвётся). Так старый клиент работает с новым агентом.

## Ввод: мышь и клавиатура (этап M1, право `input`)
Все сообщения — от клиента к агенту, ответа нет (кроме `error` при ошибке). Без права `input` агент отвечает `error` `forbidden`.

| t | Поля | Смысл |
|---|---|---|
| `move` | `dx`, `dy` (дробные) | Сдвиг курсора в пикселях. Ускорение и чувствительность считает клиент; дробные остатки агент копит сам. |
| `button` | `b` (`left` / `right` / `middle`), `down` (bool) | Нажать или отпустить кнопку мыши. Так работает удержание и перетаскивание. |
| `click` | `b`, `n` (1 или 2, по умолчанию 1) | Щелчок или двойной щелчок. |
| `scroll` | `dy`, `dx` (дробные, в «щелчках колеса») | Прокрутка. `dy > 0` — вверх, `dx > 0` — вправо. Дроби дают плавную прокрутку. |
| `key` | `k` (имя клавиши), `down` (bool) | Нажать или отпустить клавишу (модификаторы, удержание Alt для Alt+Tab). |
| `keys` | `k` (массив имён) | Сочетание: нажать по порядку, отпустить в обратном. Например `["ctrl","c"]`. |
| `text` | `s` | Напечатать текст через Unicode-ввод: кириллица и эмодзи работают при любой раскладке на ПК. `\n` — Enter, `\t` — Tab, `\b` — Backspace (так телефон исправляет уже напечатанное). |

**Имена клавиш:** `a`–`z`, `0`–`9`, `f1`–`f24`, `enter`, `esc`, `tab`, `space`, `backspace`, `delete`, `insert`, `home`, `end`, `pageup`, `pagedown`, `left`, `right`, `up`, `down`, `ctrl`, `alt`, `shift`, `win`, `menu`, `printscreen`, `capslock`, `numlock`, `scrolllock`, `pause`, `volumeup`, `volumedown`, `volumemute`, `playpause`, `nexttrack`, `prevtrack`, `stop`, а также `vk:0x41` — любой виртуальный код Windows. Неизвестное имя → `error` `bad_message`.

**Безопасность:** когда соединение рвётся, агент отпускает все нажатые этим телефоном клавиши и кнопки мыши, чтобы на ПК не «залип» Ctrl или ЛКМ.

**Ограничение Windows:** программа без прав администратора не может управлять окнами, запущенными от администратора (например, Диспетчером задач), и экраном блокировки. Это снимет служба агента на этапе M6.

## Питание и мониторы (этап M1, право `power`)

| t | Направление | Поля | Смысл |
|---|---|---|---|
| `power` | клиент → агент | `a` — действие, `in` — через сколько секунд (0 или нет — сразу, до суток), `force`, `keep` | Выполнить сейчас или поставить таймер. Новый таймер заменяет старый. |
| `power_cancel` | клиент → агент | — | Отменить таймер. |
| `power_timer` | агент → клиенты | `a`, `at` (Unix-время в мс), `now` (время агента в момент отправки — часы телефона могут расходиться), `force`; без полей — таймера нет | Рассылается всем подключённым телефонам при каждом изменении и сразу после `welcome`, если таймер есть. |

**Действия `a`:** `shutdown`, `restart`, `sleep`, `hibernate`, `lock`, `signout`, `monitors_off`, `monitors_on`.

- `force` (для `shutdown`, `restart`, `signout`): не ждать программы с несохранёнными данными. Без него Windows спрашивает их, и, если какая-то программа не даёт завершить работу, компьютер останется включённым с её окном на экране.
- `keep` (для `monitors_off`): мониторы будит только `monitors_on` с телефона. Если дисплей проснулся от мыши (своей или тачпада телефона), агент через полсекунды гасит его снова — экран коротко мигнёт. Нажатие клавиши на клавиатуре ПК всегда будит мониторы и снимает этот режим, чтобы человек за компьютером не остался без экрана. Если дисплей просыпается больше трёх раз за 30 секунд, режим тоже снимается — чтобы не мигать без конца. Агент не перехватывает мышь (это вызывало бы лаги в играх): он узнаёт о пробуждении дисплея от Windows, а о клавишах — через Raw Input только клавиатуры и только пока режим включён.
- Без `keep` мониторы просыпаются от любого движения мыши или клавиши — как обычно в Windows.
- За минуту до выключения, перезагрузки, сна, гибернации или выхода на ПК появляется окно с обратным отсчётом и кнопкой «Отменить»; отменить можно и из меню значка в трее.
- Ошибка (например, гибернация выключена в Windows) — `error` с кодом `power_failed` и понятным текстом.

## Включение по сети (Wake-on-LAN, этап M3)

Сам пакет пробуждения агент не получает — компьютер в это время выключен. Телефон шлёт UDP «магический пакет» (6 байт `0xFF` и 16 раз MAC-адрес) на порты 9 и 7: на широковещательный адрес подсети (`macs[].broadcast` из AgentInfo, иначе IP с `.255`) и на `255.255.255.255`. Поэтому включать можно только из той же сети, что и ПК.

| t | Направление | Поля | Смысл |
|---|---|---|---|
| `wol_check` | клиент → агент | — | Проверить, готова ли Windows к включению по сети. |
| `wol_setup` | клиент → агент | — | То же, и открыть на экране ПК мастер «Включение по сети» (там кнопка «Исправить» с запросом прав администратора). |
| `wol_status` | агент → клиент | `ready`, `canFix`, `checks[]`: `id`, `state` (`ok` / `warning` / `problem` / `unknown`), `title`, `hint?` | Результат проверки. Тексты — от агента, на его языке. BIOS проверить нельзя, он всегда `unknown` с инструкцией под производителя платы. |

В `AgentInfo.macs[]` есть поле `broadcast` — широковещательный адрес подсети этой сетевой карты.

## Файлы ПК (этап M2, право `files`)

Файлы идут не через WebSocket, а обычным HTTPS на тот же порт: `https://<ip>:<port>/api/files/<операция>`. Сертификат тот же и так же закреплён. Телефон представляется заголовками `X-RDesk-Device: <deviceId>` и `X-RDesk-Token: <token>`; неверный токен → 401 `revoked`.

Агент открывает телефону только выбранные на ПК папки («корни», `root`) — по умолчанию Рабочий стол, Загрузки, Документы, Изображения; запись по умолчанию разрешена только в «Загрузки». Можно открыть весь компьютер (корни `drive-c`, `drive-d`…). Пути (`path`) — относительно корня, части через `/`. Выйти за пределы корня нельзя ни через `..`, ни через ссылки и точки соединения (junction) — 403 `outside` / `link`.

| Операция | Метод | Параметры | Ответ |
|---|---|---|---|
| `roots` | GET | — | `{"roots":[{"id","name","writable"}]}` |
| `list` | GET | `root`, `path` | `{"entries":[{"name","dir","size","modified"}]}` (modified — Unix мс) |
| `download` | GET/HEAD | `root`, `path` | Содержимое файла. Поддерживается `Range` — докачка с места обрыва (206). |
| `upload/begin` | POST | `root`, `path` (папка), `name`, `conflict` = `ask` / `replace` / `rename` | `{"name","have"}`: итоговое имя и сколько уже принято. При `ask` и существующем файле — 409 `exists`. |
| `upload` | PUT | `root`, `path`, `name` (из begin), `size`, `offset`, тело — байты с места `offset` | `{"have","done"}`. Если `offset` не совпал с принятым — 409 `offset:<N>`, продолжать с N. |
| `mkdir` / `rename` / `delete` / `open` | POST | `root`, `path` (+ `name` для rename) | `{"ok":true}`. `delete` — в корзину Windows; `open` — открыть файл на ПК программой по умолчанию. |

Ошибки — JSON `{"code","msg"}` с HTTP-статусом: 400 `bad_name`, 403 `read_only` / `outside` / `link` / `denied`, 404 `not_found` / `no_root`, 409 `exists` / `offset:N`.

Пока файл принимается, он лежит рядом как `имя.rdpart` (в списках не виден) и становится настоящим файлом, когда пришли все `size` байт.

**«Поделиться → на ПК»:** корень `inbox` — папка для входящих на ПК (по умолчанию «Загрузки»), всегда с записью, в списке корней не показывается. Телефон шлёт туда с `conflict=rename`; агент показывает уведомление «Файл с телефона».

## Буфер обмена (этап M2, право `clipboard`)

| t | Направление | Поля | Смысл |
|---|---|---|---|
| `clip_get` | клиент → агент | — | Попросить текст из буфера обмена ПК. |
| `clip` | агент → клиент | `text`, `image` | Текст (пустой — в буфере не текст или пусто). `image: true` — текста нет, зато есть картинка: её телефон забирает по HTTPS. |
| `clip_set` | клиент → агент | `text` | Положить текст в буфер обмена ПК. |
| `clip_done` | агент → клиент | — | Готово. |

**Картинки** идут по HTTPS (в WebSocket скриншот может не влезть), с теми же заголовками `X-RDesk-Device` / `X-RDesk-Token`:
- `GET /api/clip/image` — картинка из буфера ПК в PNG; 404 `no_image`, если там не картинка.
- `PUT /api/clip/image` — положить картинку (PNG, JPEG…) в буфер ПК, до 50 МБ. Агент кладёт и рисунок, и PNG (с прозрачностью).

## «Отправить на телефон» (этап M2, право `files`)

В Проводнике Windows: правый щелчок по файлу → «Отправить на телефон (Couchpad)» (в Windows 11 — в «Показать дополнительные параметры»). Explorer запускает `RemoteDesk.exe --send "файл"`; эта копия передаёт путь работающему агенту через именованный канал текущего пользователя и выходит.

| t | Направление | Поля | Смысл |
|---|---|---|---|
| `offer` | агент → клиент | `files[]`: `id`, `name`, `size` | Компьютер прислал файлы. Телефон сразу скачивает их в «Загрузки/Couchpad» обычной загрузкой: `download?root=outbox&path=<id>` (с докачкой). |

По случайному `id` доступен только отправленный файл, и только час. Если ни один телефон не подключён, предложение уходит первому, кто подключится в течение часа.

## Папки телефона на ПК (этап M2, право `files`)

В приложении человек сам выбирает папки телефона, которые видит компьютер (системный выбор папки Android, без разрешения «доступ ко всем файлам»), и для каждой — можно ли компьютеру записывать. На ПК их показывает окно «Файлы телефона…» в меню значка в трее. Работает, пока телефон подключён.

Запросы идут от агента к телефону по тому же WebSocket:

| t | Направление | Поля | Смысл |
|---|---|---|---|
| `pf` | агент → клиент | `id`, `op`, `root?`, `path?`, `name?`, `target?`, `file?`, `size?` | Запрос к папкам телефона. |
| `pf_r` | клиент → агент | `id` + поля ответа, или `error` (текст для человека) | Ответ на запрос с тем же `id`. Агент ждёт его до 20 с. |

| `op` | Поля запроса | Ответ |
|---|---|---|
| `roots` | — | `roots[]`: `id`, `name`, `writable` |
| `list` | `root`, `path` | `entries[]`: `name`, `dir`, `size`, `modified` |
| `mkdir` / `delete` | `root`, `path` | `ok` |
| `rename` | `root`, `path`, `name` | `ok` |
| `push` | `root`, `path`, `target` | `ok`. Телефон отправляет файл на ПК обычной загрузкой в корень `target` (`pull-…` — папка ПК, которую человек выбрал для приёма). |
| `pull` | `root`, `path` (папка), `file`, `name`, `size` | `ok`. Телефон скачивает с ПК `download?root=outbox&path=<file>` и сохраняет в эту папку. |

Сами файлы, как и везде, идут по HTTPS — с докачкой; прогресс виден на телефоне. Удаление на телефоне окончательное (корзины нет), поэтому окно на ПК спрашивает подтверждение.

## Экран дома (этап M4, права `screen` и `input`)

| t | Направление | Поля | Смысл |
|---|---|---|---|
| `screen_start` | клиент → агент | `monitor?`, `maxWidth`, `quality` (20–95), `fps` (до 60) | Начать показ монитора (без `monitor` — основной). Повторный `screen_start` переключает монитор. |
| `screen_info` | агент → клиент | `monitor`, `monitors[]`: `id`, `name`, `width`, `height`, `primary` | Что показывается и какие мониторы есть. |
| `screen_ack` | клиент → агент | `n` | Кадр `n` получен. Агент держит в пути не больше двух неподтверждённых кадров. |
| `screen_stop` | клиент → агент | — | Остановить показ (и при обрыве связи показ останавливается сам). |
| `pointer` | клиент → агент | `x`, `y` (0…1) | Поставить курсор в точку показанного монитора — касание на картинке. Дальше обычные `click` / `button`. |

**Кадры** — бинарные сообщения WebSocket: `[1 байт: 1][4 байта: номер][2 байта: ширина][2 байта: высота][JPEG]`, числа big-endian. Кадр уходит, только если экран изменился, поэтому на неподвижном экране сеть почти не занята. Пока — JPEG через GDI (BitBlt) с курсором, около 15 кадров в секунду для 1080p; H.264 и захват через видеокарту — позже.

На ПК, пока телефон смотрит экран, подсказка у значка в трее говорит «… смотрит экран», а при начале показа всплывает уведомление. В окне UAC Windows не даёт снимать экран — картинка замирает до выхода из него. Экран блокировки и входа виден, если включена служба входа (ниже).

### Звук ПК (право `screen`)

`{"t":"audio_start","mute":true,"bitrate":128000}` — слать телефону то, что играет в колонках ПК (WASAPI loopback устройства вывода по умолчанию). `mute` — пока идёт звук, громкость колонок ПК в ноль (не Mute: на части звуковых карт выключенный звук приходит в запись тишиной); после `audio_stop` или обрыва связи громкость возвращается, если её за это время не меняли на ПК. Прежняя громкость записана в `speakers-volume.txt` в папке данных — после падения агента она вернётся при следующем запуске. Приложение просит 128 кбит/с дома и 64 кбит/с через интернет.

**Кадры звука** — бинарные сообщения WebSocket: `[1 байт: 2][4 байта: номер, big-endian][пакет Opus]`, 20 мс, 48 кГц, стерео. Подтверждать не нужно: у агента очередь на 200 мс, лишнее выбрасывается. Пока на ПК тишина, кадров нет. Ошибка (нет звукового устройства) — `error` `forbidden`.

## Вход в Windows с телефона (служба входа)

Включается в трее: «Вход в Windows с телефона» (окно UAC). Копия агента ставится в `%ProgramFiles%\Couchpad`, служба `CouchpadSignIn` работает от имени системы, брандмауэр разрешает её для частной сети. Журнал — `%ProgramData%\Couchpad\signin.log`.

Служба держит **помощника** (`--desktop-helper`) в сеансе за монитором, на текущем рабочем столе ввода (экран входа, блокировки или обычный). Помощник действует, только пока в сеансе никто не вошёл или он заблокирован:

* **Агента пользователя нет** (компьютер только включили) — помощник сам слушает тот же порт с тем же сертификатом и списком телефонов. В `welcome` у него `"signin":true` и права `input`, `power`, `screen`; `pair` отвечает `error` `forbidden`, файлы и буфер обмена — `forbidden`. После входа в Windows помощник закрывает соединения (`bye`), а клиент сам переподключается к обычному агенту (пробует до 90 с).
* **Агент пользователя работает, компьютер заблокирован** — агент снимает экран и нажимает через помощника по именованному каналу `\\.\pipe\Couchpad.Desktop.<сеанс>`. Агент пользуется каналом, только если его владелец — система; помощник принимает только клиентов своего сеанса. Для телефона ничего не меняется.

## Не из дома (проброс порта, этап M5)

Своего сервера связи у проекта нет. Чтобы подключаться с мобильного интернета, на роутере пробрасывают TCP-порт агента (по умолчанию 47800) на ПК, а в приложении указывают адрес дома в интернете — имя DDNS или постоянный IP (тот же, что для включения по сети, `SavedPc.wakeHost`; порт из него — только для пакета WoL). Подойдёт и свой VPN (Tailscale и т. п.): тогда адрес ПК в VPN.

* Клиент пробует домашние адреса одновременно, а адрес в интернете — через 1,5 с (тайм-аут 8 с): дома побеждает Wi-Fi. Первое ответившее соединение остаётся, остальные закрываются; ответ агента с ошибкой окончательный.
* Протокол тот же: TLS с закреплённым сертификатом, вход по токену. Через интернет экран запрашивается экономнее: до 1280 px по ширине, качество 50, 15 кадров/с.
* Агент принимает `pair` только с домашних адресов (10/8, 172.16/12, 192.168/16, 169.254/16, 100.64/10 — Tailscale, loopback, IPv6 fc00::/7 и fe80::/10). С остальных — `error` `forbidden`: сопрягают, стоя рядом с ПК.

## Отзыв доступа
В агенте пользователь удаляет телефон из списка → его токен стирается, текущее соединение закрывается с `error` `revoked`. Клиент помечает компьютер «доступ отозван» и предлагает сопрячь заново.
